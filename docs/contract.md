# 组织温室气体盘查数据契约 v3

v3 在 v1 的一次性全量盘查与 v2 的「电力证书修订台账」之外，新增按持有时点把集团
Scope 1/2 合并的口径。三种入口互斥；`--source/--output` 的原始输入、校验严格度和
报告字节行为完全不变（v1 报告仍为 `schema_version=1`）。

## 1. 遗留全量模式（v1，保持不变）

`carbon-inventory --source <input.json> --output <report.json>`

组织环境数据分析者按活动记录和显式因子表计算 Scope 1/2 排放。活动字段
id/organization/date/scope/category/quantity/unit/factor_id，最多 20000；因子最多 1000，
rate 为非负整数有理分数 kgCO2e/unit（字符串 `n/d`），日期区间 `[valid_from, valid_to)`，
null 表示无结束。日期严格 ISO 日历日。活动数量为 0..10^12 整数，单位必须与因子精确匹配，
因子类别和有效期也必须匹配。任何未知/重复因子 ID 或错配都拒绝；factor 来源及版本由调用方负责。
每笔排放 = quantity × rate，精确 Fraction kgCO2e；按组织和 scope 分组，同时保留逐活动证据
与采用因子。空活动允许，输出空分组。样例用电 1000 kWh×2/5=400 kgCO2e，
燃气 100m³×19/10=190，总计 590。报告 `schema_version=1`，含源字节 SHA256。

## 2. 修订台账模式（v2 新增）

`carbon-inventory --registry <ledger.db> --batch <batch.json> --output <report.json>`

`--source` 与 `--registry` 互斥；registry 模式必须同时提供 `--batch`。数据库、批次、输出
三个路径必须互异，且数据库与输出均拒绝符号链接。数据库首次使用时为空且 `generation=0`。
批次 JSON 与源 JSON 共用同一受限解析器：最多 8MB、拒绝重复键、拒绝非有限数值、未知字段拒绝。

### 2.1 批次结构

批次严格且仅包含 `batch_id`、`base_generation`、`changes`：

- `batch_id`：非空白标识符（沿用 v1 标识符规则，≤128 字符）。
- `base_generation`：非负整数；新批次仅当它等于数据库当前代时才可接纳。
- `changes`：数组，每项严格为 `{kind, id, value}`。`kind` 仅允许
  `factor`/`activity`/`certificate`；同一批次内同一 `(kind, id)` 最多出现一次。
- `value` 为 `null` 表示删除，删除当前不存在的对象拒绝；否则为完整替换对象，
  其内部 `id` 必须与变更目标 `id` 一致，不允许部分字段补丁。
- 先应用全部变更，再对最终状态做整体校验；因此变更的书写顺序不影响含义，
  最终引用非法（如指向已删除因子）时整批拒绝，不留下部分变更。

### 2.2 实体规则

- 因子：字段与 v1 完全相同（id/category/unit/kgco2e_per_unit/valid_from/valid_to），
  率为非负有理 `n/d`，区间左闭右开且必须非空。
- 活动：沿用 v1 字段与校验（类别、单位、因子有效期、0..10^12 整数数量、ID 唯一）。
  本模式下所有 scope=2 活动单位必须为 `kwh`，并额外携带 `residual_factor_id`；
  scope=1 活动不得携带该字段。`factor_id` 仍用于 location 口径，
  `residual_factor_id` 用于未被证书覆盖电量的 market 口径，两者按同样的类别、单位和
  活动日有效性校验。
- 证书：字段为 id/eligible_organizations/valid_from/valid_to/quantity/kgco2e_per_kwh。
  资格组织列表为非空字符串数组且无重复；日期左闭右开，`valid_to` 可为 null；
  quantity 为 0..10^12 整数；排放率沿用因子的非负有理数约束（`n/d`）。
- 上限：证书最多 100 张，scope=2 活动最多 300 笔；因子最多 1000、活动总数最多 20000。

### 2.3 批次身份与重放

规范批次内容 = JSON 对象键排序、`changes` 按 `(kind, id)` 排序后计算的 UTF-8 SHA256；
不对字符串或分数做等价化简（`1/2` 与 `2/4` 视为不同内容），除此之外按严格原值判等。

- 相同 `batch_id` 且规范内容相同：重放。重放判断优先于 `base_generation` 检查，
  返回该批次原代存储的报告字节，不重新推进代数，也不按当前因子或当前分配重算历史。
- 相同 `batch_id` 但规范内容不同：拒绝。
- 新批次仅当 `base_generation` 等于当前代时接纳，成功恰好把代数加一。

### 2.4 全局分配与四层核算

仅 scope=2 的整数 kWh 可分配到合法的（证书, 活动）对。合法条件：活动组织在证书资格表内，
且活动日落入证书 `[valid_from, valid_to)` 区间。每张证书分配总量不超过 quantity，
每个活动分配总量不超过耗电量。按以下顺序做字典序优化，每层只在前层最优解集合内比较，
不使用浮点近似，也不用固定权重把目标折叠成一个数：

1. 最大化覆盖电量；
2. 最小化全部 market 排放；
3. 最小化与上一已接受分配的总绝对变动量；
4. 最小化分配向量字典序。

分配向量按合法对的（证书 ID, 活动 ID）排序，包含零分量。变动量按前后两代所有对的并集
逐对求绝对差之和；已删除或已失效的对当前值视为 0；首代的前值全为 0。

求解为一次精确的单阶段最小费用流，全程只用整数与 `Fraction`，无浮点、无固定权重折叠：

- 网络为 源→证书→活动→汇。每条合法对边携带有序复合费用
  `(market 位, 变动斜率, 格点单位向量)`，三个分量分别按分量相加、整体按字典序比较，
  因此一次最小费用流同时满足四层目标的优先级，不会把任一目标折叠成近似权重。
- 所有（证书率−残余率）分数先乘统一公分母转为整数；再用位置基数把 market 贡献放在高位、
  变动斜率放在低位，基数严格大于任一层级可达的下级总量。第三分量是按合法对索引排序的格点
  单位向量，其字典序即分配向量的字典序。
- 凸函数 `|x − 上代值|` 用每对至多两条分段边编码（`[0,prev]` 段斜率 −1、其后斜率 +1），
  段宽为容量而非单位电量，故迭代次数只取决于图中的段数（O(边数)），不按 10^12 单位电量
  逐次枚举。最短路由一次 SPFA 建立可行 Johnson 位势后改用 Dijkstra，复合费用支持任意精度
  整数与格点序比较。

market 排放 = 已分配电量 × 证书率 + 未覆盖电量 × residual 因子率；location 排放始终由原
`factor_id` 计算；scope=1 两个口径结果相同。

### 2.5 报告（`schema_version=2`）

每次接纳或重放输出确定排序的 JSON，包含：`generation`、`batch_id`、规范 SHA256、
正数分配边、每张证书剩余量、逐活动的覆盖/未覆盖 kWh 与两个口径排放、
按（组织, scope）的两个口径合计，以及四层目标值（分配向量含零分量，并给出向量对应的
合法边顺序）。所有排放以约分后的 Fraction 字符串表示。

### 2.6 存储、发布与恢复取舍

单 SQLite 文件内保存：当前实体三张表、当前代与每代完整分配、不可变批次表
（批次身份、基代、规范 SHA256、原始内容与该代报告字节）。实体、整张分配和可重现报告
在同一数据库事务内提交；校验、优化或提交前失败时旧代与旧报告均保持不变。

报告文件在数据库之外，沿用原子替换与符号链接防护。若数据库已接纳而报告写入失败，
进程退出 2 并在 stderr 明确该代已接纳；用同一批次重放即可修复文件而不会再次接纳。
后续代已成功后再重放旧批次，输出旧代报告的相同字节，当前代与当前分配不倒退。

明确的取舍：本工具面向单操作者批处理，只保证 SQLite 单事务级一致性，不承诺多进程并发
写入、网络可用性或断电级 fsync 耐久；报告文件与数据库之间的崩溃间隙由「重放修复」覆盖，
而非两阶段提交。

## 3. 集团合并模式（v3 新增）

`carbon-inventory --source <input.json> --boundary <boundary.json> --root <org> --output <report.json>`

`--boundary` 与 `--root` 必须同时出现且只与 `--source` 搭配；`--batch`、`--registry`
不能与它们组合，`--batch` 仍只属于 `--registry`。
source、boundary、output 三个路径必须互异。活动与因子沿用 v1 的全部规则、精确 Fraction
和因子日期匹配（含 `[valid_from, valid_to)` 左闭右开），旧模式不改；本模式额外读取边界并
输出 `schema_version=3` 的合并视图，源与边界的原始字节 SHA256 一并保留。边界与源共用
同一受限解析器：最多 8MB、拒绝重复键、拒绝非有限数值、未知字段拒绝。

### 3.1 边界文档

边界 JSON 严格且仅含 `relationships` 数组，最多 50000 条；每条严格为
`{parent, child, share, operational_control, valid_from, valid_to}`：

- `parent`/`child`：v1 标识符规则；边界中出现过的组织与活动组织合并去重后最多 10000 个。
- `share`：0..1 的非负有理数字符串 `n/d`（十进制数字、分母 ≥1、值不超过 1）。
- `operational_control`：必须是 JSON 布尔值，`0/1`、字符串、null 都拒绝。
- `valid_from`/`valid_to`：ISO 日历日，区间左闭右开，`valid_to ≥ valid_from + 1` 或为 null。
- 同一 `(parent, child)` 对的有效边不得重叠；首尾相接（`end == 下一条 start`）允许。
- 上限：关系最多 50000 条；活动沿用 v1 的 20000 笔与因子 1000 张上限。

校验在全时间轴上进行，而不是只看有活动的日期：

1. 任一日期的每个孩子收到的有效直接持股比例总和不得超过 1；
2. 完整时间线上任意有效图都必须无环——即使成环的日期区间没有任何活动，也整份拒绝。

### 3.2 时点切片

边界索引把所有 `valid_from`/`valid_to` 端点排序，扫描时先让到期边失效、再让新边生效。
因此某日等于 `valid_to` 时该边已不在图中，等于 `valid_from` 时已生效。活动日按二分映射到
唯一端点区间；同一区间内的活动共享同一次精确求值。`BoundaryIndex.states` 按活动日期惰性
推进这同一条事件流，不预展开路径。

### 3.3 两种口径

对选定 root，按每笔活动的日期切片取唯一有效边集：

- equity：`w[root]=1`，`w[v]=Σ_{u→v 有效} w[u]·share(u,v)`。root 到活动组织的所有有效路径
  的 share 乘积精确相加，汇聚路径必须求和；权重与活动排放相乘得到 equity 金额。
- operational-control：从 root 出发做布尔可达性，只有路径上每条边都是
  `operational_control=true` 才置真；同一组织即使有多条受控路径也只计一次完整排放，
  否则为 0。root 自身两口径权重均为 1。

实现上只在每个切片做一次拓扑遍历，并裁剪到“活动组织的祖先”集合；多条路径的乘积由递推
自然合并，绝不枚举路径。图遍历代价为每个被活动使用的切片 O(组织数+有效边数)，与路径条数
无关，因此指数级路径（例如 2^25 条）也只需毫秒级。精确结果本身的分子/分母可能长达上万位
（50000 条边的乘积），这部分大整数运算代价取决于精确数值的位数，而不是路径条数。

### 3.4 报告（`schema_version=3`）

顶层为 `schema_version`、`source_sha256`、`boundary_sha256`、`consolidation`。
`consolidation` 含：

- `root`；
- `activities`：按活动 id 排序，逐活动给出 `id/organization/date/scope/kgco2e` 以及
  `equity_share/equity_kgco2e/control_share/control_kgco2e`，全部为约分 Fraction 字符串；
- `totals`：按 scope 升序的两口径金额合计（`equity_kgco2e`、`control_kgco2e`）；
- `unattributed_activities`：两口径权重都为 0 的活动 id 列表。

不输出路径枚举。空活动允许，`activities`、`totals`、`unattributed_activities` 均为空数组。

### 3.5 设计记录：最简实现为何会漏约束，以及两种可行设计

**最简实现为何不够。** 只在“有活动的日期”上采样校验、或把 `valid_to` 当作闭区间、
或只在被 root 触及的子图上查环，都会让约束漏网：

- 只在活动日校验持股总和与环，会放过没有任何活动的短暂环或超额区间；需求明确要求
  完整时间轴上任何有效图都无环。
- 把 `[valid_from, valid_to)` 实现成闭区间，会让到期日同时保留旧边：合并层随后就会用
  过期关系计算归属，这正是需求点名的联动失败（本仓用
  `test_stale_slice_regression_would_be_detected` 与到期日切片测试固定该行为）。
- 只把 control 当成“加权份额”，会在多条受控路径汇聚时重复计入；只把 equity 当成
  “取最大路径”，则漏掉汇聚路径的求和。

**方案 A：按所有边界端点预建并验证时间切片，再批量归属。** 对排序后的每个端点区间构造
一份不可变有效边集，逐片校验持股总和与环（可在扫描中增量维护拓扑序），然后把活动按日期
路由到对应切片批量计算。优点：每片与校验图严格一一对应，端点归属、半开区间语义和环检查
用同一份数据，验证与计算不可能错位；缺点：若端点很多，需要保存/遍历所有切片，即使某些
区间没有活动。

**方案 B：先全局验证，再按活动日期惰性折叠 DAG。** 先在完整时间轴扫描一次做持股总和与
环检查（与方案 A 相同的事件流），再只对实际出现的活动日期推进同一事件流，返回该日期的
唯一有效边集。优点：只为有活动的区间付出合并计算，活动日期远少于端点时更省；缺点：必须
保证惰性游标与验证扫描使用同一套“先过期、后生效”规则，否则会退回过期边。

本仓采用 B：`BoundaryIndex` 构造时完成全时间轴验证，`states()` 惰性产出活动日期的活边
邻接；两者共享端点表和半开区间处理，活动日期的切片键由 `day_key()` 二分得到，因此不会
出现“校验用一套图、合并用另一套图”。两种设计都必须保持半开区间语义，且都不改变
`--source/--output` 旧报告字节。

**验收对照。** `tests/test_group.py` 用独立的全简单路径枚举（`brute_attribute`）对照小图
的多路径 equity 与布尔 control；随机图、随机区间边界也与逐日暴力校验对照；另有
2^25 条不同路径的菱形图在毫秒级得到精确 `1/2`，以及 10000 组织/20000 活动/50000 关系的
上限规模用例，证明实现不按路径条数展开。

## 4. 共享风险自适应核查（v4 新增）

`carbon-inventory --source <input.json> --uncertainty <spec.json> --output <report.json>`

`--uncertainty` 只与 `--source` 配对，和 `--registry`、`--batch`、`--boundary`、`--root`
全部互斥。source、uncertainty、output 三个路径必须互异；输入沿用同一受限 JSON 解析器
（8MB、拒绝重复键、拒绝非有限数值、未知字段拒绝），输出沿用符号链接防护与原子替换。
v1 全量盘查、v2 台账、v3 集团合并的输入、错误与输出字节都不因本模式改变。

### 4.1 INPUT

`--source` 沿用现有 `activities/factors` 校验（字段、类别、单位、日期半开区间、因子匹配、
数量 0..10^12）。本模式额外要求活动 ID 唯一，活动最多 40 项、因子最多 16 项；超出即拒绝。
`nominal` 就是旧 `analyze(INPUT)` 的结果，只作参考，不参与求界。

### 4.2 SPEC

`--uncertainty` 严格且仅含 `variables`、`constraints`、`quantities`、`rates`、
`audit_costs`、`precision` 六个字段。

- `variables`：0..10 个不重复 ident。输出 `variable_ids` 为按字符串排序后的顺序，
  该顺序定义完整 0/1 向量的字典序，所有见证数组都按它排列。未被表达式引用的变量允许。
- `constraints`：最多 100 项，每项严格为 `{id, terms, lower, upper}`。`id` 唯一；
  `terms` 是变量 ID 到有符号整数系数的对象，系数绝对值 ≤10^6，可含空对象（按 0 计）；
  `lower`/`upper` 为绝对值 ≤10^12 的整数且 `lower ≤ upper`，含义是
  `lower ≤ Σ coeff·x ≤ upper`。引用未知变量、布尔或其他非整数系数一律拒绝。
- `quantities`：每项严格为 `{activity_id, terms}`，同一活动最多一项。
  `quantity(x) = 源 quantity + Σ coeff·x`，系数为绝对值 ≤10^12 的有符号整数。
  未列出的活动保持名义数量。
- `rates`：每项严格为 `{factor_id, terms}`，同一因子最多一项。
  `rate(x) = 源 kgco2e_per_unit + Σ coeff·x`，系数为有符号 `n/d` 字符串，
  `|n| ≤ 10^12`、`1 ≤ d ≤ 10^12`。未列出的因子率保持名义值。
- `audit_costs`：覆盖全部变量 ID 的对象。值为 0..10^6 整数（核查一次该变量并观察其
  真实 0/1 答复的成本）或 `null`（不可核查）；布尔拒绝。
- `precision`：恰含 `overall` 与非负 `n/d`，和 `groups`。`groups` 每项恰为
  `{organization, scope, tolerance}`，必须恰好覆盖源数据出现的每个组织/scope 一次；
  tolerance 为分子 0..10^12、分母 1..10^12 的非负 `n/d`。

情景数量是精确整数、率是 `Fraction`；求值结果不再套名义值的 10^12 上限。因子类别、单位、
有效期与活动日期始终取源值，本模式不改变它们。

### 4.3 Ω 与物理合法性

Ω 是所有满足全部线性约束的变量赋值构成的状态集合（空变量时唯一状态为空向量）。
排放定义为 `Σ_活动 quantity(x)·rate(x)`，同一变量跨活动与因子始终同值。

物理合法性由 Ω 整体负责：每个可行状态必须让所有活动数量非负、所有源因子率非负——
包括未被任何活动引用的因子。任一步情景出现可行负值，整次退出 2，stderr 定位到具体对象
（活动或因子）、完整反例向量与该负值。只被约束排除的负值状态不参与该检查，因此不会误拒。
Ω 为空时正常输出 `status=infeasible`，不以名义全 0 状态代替。

空活动时总排放为 0，但仍审查全部因子率的物理合法性。

### 4.4 后验与精确区间

给定已观测变量及其答复 O，后验 Ω_O 只保留与 O 一致的状态。对逐活动、每个组织/scope 组和
整份盘查分别计算精确最小/最大排放及完整见证，端点并列时取完整向量字典序最小者。界值为
约分 `Fraction` 字符串；约束判断、乘积和见证回代全程整数/Fraction，禁止浮点容差。
组与 overall 必须跨越共享变量统一求极值，不能把各活动或各组独立极值相加。

### 4.5 非预知核查策略

策略按可达观测递归定义。若当前后验的 overall 与每个组区间宽度都已不超过对应 precision，
该节点立即停止并输出该后验的精确 `groups` 与 `overall` 区间。否则只能选择一个尚未核查、
成本非 `null`、且两种答复都仍可行的变量；被约束或已有答复唯一确定的变量视为已知，不付费
核查；未被选择前不读取其真实值。两种答复分支都必须继续策略。

目标是最小化从当前后验开始的最坏累计成本：`worst = cost(v) + max(分支0, 分支1)`，成本在
得到答复前支付，每个可达子状态都采用自身的最小最坏剩余成本。并列时选变量 ID 最小者，
两个分支递归遵守同一规则。不可达答复不进入最坏成本，也不作为失败分支；只剩一种答复的
变量没有查询节点。零成本变量同样终止：沿任一路径同一变量最多核查一次，已经满足精度时
不得添加零成本节点。

若某些可行状态在核查所有可核查变量后仍无法达到精度，`audit.status=impossible`，
`worst_cost`/`policy` 均为 `null`，并给出完整可核查答复集合 `observations`，以及在这些
答复下某目标的两个精确端点见证（两者可核查变量取值相同，差超过 tolerance）。

### 4.6 报告（`schema_version=4`）

顶层为 `schema_version`、`source_sha256`、`uncertainty_sha256`、`variable_ids`、
`status`、`nominal`、`activities`、`groups`、`overall`、`audit`。

- Ω 非空：`status=feasible`。`activities` 按 ID 排序、`groups` 按组织/scope 排序，
  每项含 `minimum`、`maximum`、`min_witness`、`max_witness`；见证为完整 0/1 数组。
- Ω 为空：`status=infeasible`，`activities`/`groups` 为空数组，`overall` 与 `audit`
  为 `null`。
- `audit.status=possible`：给出 `worst_cost` 与完整 `policy`。查询节点含 `variable`、
  `cost`、`worst_cost`、`zero`、`one`；停止节点含该后验的 `groups` 与 `overall`
  精确区间。
- `audit.status=impossible`：`worst_cost`/`policy` 为 `null`，附 `witness`。

### 4.7 设计记录：三种实现的取舍与验收

**最简一次情景 DFS 加固定问题顺序为何不够。** 这种实现只沿“先枚状态、再按预先固定顺序
逐个核对变量”的一条路径走，从不重算后验，因此：它把提问顺序当成已知，违反非预知性；
它不针对每个可达后验重新求界，答复带来的相关性收缩（例如 `x` 与 `1-x` 相加）无法提前
停止；它会把不可达答复当成正常失败分支，或把“仍有精度超标且不可核查”的分支当成可解；
它也无法给出 `impossible` 的反例，因为从未枚举“所有可核查变量都已答复”的后验。最坏成本
不是沿固定顺序求和，而是在每个子状态上取自身最优：同一个变量在 `x=0` 后可能完全无关，
在 `x=1` 后才成为关键问题。

**方案 A：直接建立精确后验代价函数。** 对每个后验掩码递归求
`cost(mask) = 0`（已满足精度）或 `min_v [c_v + max(cost(mask∧v=0), cost(mask∧v=1))]`，
不可解返回 `None`。义务：必须把“两种答复都可行”作为选点条件（不可达分支不进入最坏值）；
约束或已有答复确定的变量不得作为候选；零成本变量要能推进，因此递归不能因预算不变而重复
访问同一掩码；`None` 必须向上传播，让任何包含不可解子后验的候选问题都失去有限成本。
本仓 `strategy.Policy` 即此设计，掩码记忆化保证每个后验只算一次。

**方案 B：按预算判可实现再提取策略。** 先问“在预算 B 内能否对每个可达答复都达到精度”
（判定递归），二分得到最小 B，再按同一判定提取每个节点的最小 ID 最优变量。义务：判定函数
必须与代价函数同义（`feasible(mask, B)` 当且仅当 `cost(mask) ≤ B`），零成本推进要以
“剩余可核查变量集合”单调收缩为终止依据，不可达答复不得被当作成功分支；提取阶段必须为
每个分支递归建立自身最小预算，不能拿根预算余量放松子状态。本仓 `strategy.Budget` 即此
设计，并在报告回代时与方案 A 逐节点比对。

**为何两者都要有。** 方案 A 直接、易读，是本仓生产实现；方案 B 独立地重述“预算是否可
实现”，若不共享掩码与候选定义就会暴露 A 的漏项。二者都必须对 `None`（不可解）与
停止优先级给出同一答案；任何分歧都视为实现错误。

**回代发布。** `audit.run` 在构造报告后调用 `verify.verify`：重新解析源与规格、重新枚举
Ω、用纯 `Fraction` 重算所有排放，逐字节核对 nominal、初始区间、每个停止节点的后验区间
（并确认其确实满足全部 precision）、每个查询节点的成本结构与两种答复可达性、根
`worst_cost`、以及 `impossible` 反例的见证一致性；同时确认方案 A 与方案 B 的完整策略树
相同。任何不符转为 `ValueError`，进程退出 2，旧输出保持不变。

**测试对照。** `tests/test_audit.py` 的 `Oracle` 独立实现 Ω、后验端点、见证与
minimax 递归（不用掩码、不引用报告代码），在固定实例与 25 组随机实例上逐后验比对
Ω 合法性、端点值、并列见证、子策略最坏成本与并列选点，并比较方案 B；另有约束导致的
不可达答复、免费无关变量、分数微差、共享因子、跨组目标、`null` 成本、10 变量全枚举、
以及 v1/v2/v3 回归用例。10 变量上限允许一次枚举全部有限状态，策略正确性由逐后验对照
保证，而不是由规模论证代替。
